# 路线 AI 监视插件

软件界面不提供监视入口。仅手动输入 `/ai-monitor` 访问；部署地址为 `http://6.6.6.6:18080/ai-monitor`。仅网站现有账号 SilntRavn 有访问权限，使用该账号原有的网站密码验证，沿用网站登录会话。其他账号访问任何监视接口均返回 403，未登录返回 401。页面提供身份验证表单，不建立独立账号或密码。监视页每两秒刷新，可在另一个标签页同时规划路线。

开发模式默认记录，`ROAMLY_AI_MONITOR=0` 可关闭。生产模式默认关闭；在 `.env` 设置 `ROAMLY_AI_MONITOR=1` 并重启可开启。关闭后不记录新交互，历史数据保留但接口不可访问。

一次用户消息对应一条交互记录，关联原会话 ID，包含：

- 用户原始消息、历史对话、已有行程和偏好快照。
- 每次真实模型请求的完整 body：system/user/assistant/tool 消息、工具定义、模型、temperature、max_tokens、thinking 和强制工具选择。
- 每次 HTTP 尝试的原始返回、状态、耗时和异常；原始返回含服务提供的 token usage。重试与原请求使用同一 callId。
- 约束提取、工具参数和结果、交通核验、候选行程、拒绝原因和模型修正反馈。
- 最终输出、失败、取消或超时。服务重启时未结束记录标为「服务中断」。

「约束 / 调教」筛选查看实际生效的约束、候选草稿与核验反馈；「提示词 / 模型」查看每轮真实请求。系统重整上下文后的新提示词也会按实际发送内容记录。记录不包含模型内部训练参数、未返回的思维过程或此前未记录的历史交互。

记录存储于项目现有 SQLite 数据库 `data/roamly.sqlite`（或 `ROAMLY_DB` 指定的位置；当前部署为 `data/production.sqlite`），按账号保留最近 50 次已结束交互，运行中的记录不会被清理。接口沿用 HttpOnly 登录会话和同源写入保护，在服务端验证 SilntRavn 身份，只允许访问自己的记录。可导出 `.json`，删除已结束记录；注销账号同时删除该账号记录。记录含用户行程和对话，因此导出文件也应按私人资料保管。请求认证头不记录；结构化的密码、API Key、Cookie 等字段会隐藏。

插件不修改提示词或模型配置。记录失败仅报告服务端日志，不影响规划。景点资料后台预加载不是规划模型调用，不在监视范围内；规划开始前被登录校验、限流或参数校验拒绝的请求也不会生成交互记录。
