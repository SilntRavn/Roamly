# 附近探索与推荐笔记

探索页不读取当前行程或行程路线，也不自动请求浏览器或手机的实时定位。保留手动定位按钮，只有用户点击时才获取位置并移动地图。推荐以当前可见地图区域的屏幕中心点为中心，固定为附近10公里，不显示中心指示物。范围内拖动、缩放、调整面板不改变推荐和排序；地图中心移出该范围后自动重新查询，用户也可手动刷新笔记。距离以固定推荐中心为参考，不代表用户位置；离开笔记返回保留之前的地图视角和推荐范围。

区域视图和地图锚点保留在浏览器本地存储中。返回探索、重新打开笔记、切换到已读分类、重载页面或重新打开应用时，先直接显示缓存；未完成的整理任务恢复状态轮询。失败状态也缓存，切换不触发重试；只显示正在整理的进度，不显示整理失败提示。服务端按笔记关联地点的 `places.payload.location` 坐标读取SQLite中当前圆形范围内的全部笔记，不限于某个中心点、旧5公里分组或前6条。空的区域缓存不会遮住已有笔记；有数据库内容时先返回已有地点和笔记，跳过高德查询。同半径、中心偏移不超过1公里的区域仍可复用整理状态。

自动生成只补充数据库不足的区域，根据当前分类内有效地点、真实评价和已核验的推荐价值分档：没有相应游玩资源的区域下限0篇，资源稀疏的区域1篇，普通区域4篇，优质资源集中区域8篇。工厂、住宅或服务设施数量不会增加景点下限。数据库数量达到下限就不调用内容模型；不足时按差额尝试补充，不为凑数量编造内容。邻近中心与不同用户共享24小时自动尝试冷却，空结果和失败也计入，用户手动整理可主动重试。期间保留范围内已有笔记，成功追加新内容，失败、排队或没有新结果都不覆盖原列表。

笔记初始展示6篇，每次“查看更多”追加4篇，直到加载完范围内数据库笔记。全体用户的收藏数高者优先，同收藏数随机排序；已展示笔记顺序和已展开数量保留，后续同步只更新内容和未展示部分的排序。景点、美食、住宿、玩乐的地点均初始展示10个，每次“查看更多”追加10个，按本地用户评价均分、高德有效评分、已保存AI评分依次取可用分数降序，无评分地点不伪造分数。公开笔记库跨账号共享，探索页可见期间每15秒通过 `/api/explore/stored` 读取数据库更新，回到前台、恢复网络和收藏变化时也同步；这一接口不触发地图查询或生成。新增笔记通过现有列表和“查看更多”展示，并提示新增数量，已加载内容保持稳定。

顶部只保留景点、美食、住宿、玩乐四个分类滑块，复用“我的行程”的MotionTabs组件、分段控件尺寸、页面左右留白及选中滑块动画，不再显示外层白色卡片与标题。分类栏、定位按钮和笔记面板统一使用同一透明度和模糊强度的毛玻璃背景。高德周边查询按分类取样，并根据完整POI类型过滤；学校、景区管理处、停车场等不作为推荐地点，KTV、桌游、剧本杀、密室等归入玩乐。地图标记使用SVG图形；静态地图模式也显示可点击地点。分类切换不改变用户的地图视角。

笔记面板默认约占页面一半，支持收起、中间、展开三档。拖动把手或上下滑动列表可切换，列表展开后正常滚动；把手和标题旁的箭头也可点击切档。面板不显示底部三个布局按钮、范围副标题及AI整理脚注，将空间留给笔记列表。

笔记卡片保留原有双列图文布局，上方封面、下方白色文字区；文字只显示最多三行的标题，不显示地点数量、标签、导读、更新时间或来源徽章，右上角爱心可以收藏/取消收藏。下方推荐地点卡片采用项目的27px圆角、图片阴影和毛玻璃标题区，加入行程的小飞机位于毛玻璃右下角，不带圆形底。地图选中标记不显示红色外框。笔记详情使用与地点详情相同的图片封面、浮动返回/爱心按钮和毛玻璃标题，正文保留摘要、分段内容与原文来源。

“我的行程”保留全部行程、已收藏行程、收藏笔记三栏，收藏笔记栏只列出当前用户已收藏的笔记，没有灵感草稿。旅行足迹移到个人页“我的收藏”下方的入口，继续支持查看已完成行程及单独移除足迹。笔记收藏保存在 `note_favorites`，与地点/行程收藏独立；支持跨设备同步、访客登录后合并以及账号注销时清除，公开笔记刷新后仍可在收藏里查看。

## 内容链路

1. `/api/explore/nearby` 优先按地点坐标汇总共享数据库笔记与地点；完全未命中时按固定中心、10公里半径和分类查询高德，圆外的点位不纳入结果。排除小区、社区公园、文化广场、景区附属凉亭/牌坊、学校及服务设施；根据资源质量与数据库数量决定是否补充，最多取24个候选，异步调用已有的 `ARK_CONTENT_*` 内容模型配置。
2. 通过方舟 Responses API 的 `web_search` 工具搜索公开游记、体验和推荐文章。小红书仅作为可能搜到的公开网页来源，不承诺拿到登录后可见的帖子，也不运行登录态抓取。可使用马蜂窝、携程游记、旅游媒体等其他公开来源。
3. 模型先根据公开游记和用户体验判断游览价值，输出是否值得推荐、理由与真实引用。有特色且有体验证据的小众景点可以保留，普通社区设施、只有商家广告或没有游览证据的地点不推荐。再输出统一的标题、导读、标签、分段摘要、地点ID和段落来源URL。景点笔记及下方推荐卡片只接受AI评判通过的地点；评判和每段摘要都必须引用本次工具返回的真实 `url_citation`，地点ID必须属于本次核验的POI，否则不保存。摘要不冒充亲历体验，不复制原文长段落。
4. `explore_notes` 保存笔记正文、关联地点ID、推荐理由与来源，地点坐标持久保存在 `places`；`explore_feeds` 记录整理状态、区域质量和自动尝试时间，不作为笔记可见性的唯一依据。旧分组与未分组的有效笔记也按坐标返回。同一区域并发请求合并，全局最多两个整理任务。成功、空结果和失败状态均固化，普通访问优先复用；未达质量下限时受共享冷却限制补充。网络临时中断最多短重试一次，持续失败可以手动重试。刷新失败保留旧笔记。服务进程中断后的任务转为可重试状态。
5. 前端轮询整理状态，地图地点不必等待AI，下方景点卡片等待筛选结果。详情页保留每段原文链接，地点卡片跳转软件内详情，卡片右下角的小飞机可选择现有行程或新建行程，然后直接进入与该行程持久关联的AI对话。

地点来自高德当前范围内的有限取样，不代表覆盖区域内的所有商户。地图先避让图标，再隐藏拥挤的名称；名称放不下不会让对应图标一起消失，静态和矢量地图采用同一规则。不存在有可靠来源的内容时显示空状态，不生成示例帖子。精确营业、价格和预约信息以地点详情或商户确认为准。

## 接口

| 接口 | 用途 |
| --- | --- |
| `GET /api/explore/nearby?west=&south=&east=&north=&category=` | 获取四类地点和笔记状态 |
| `GET /api/explore/stored?west=&south=&east=&north=&category=` | 按坐标读取共享数据库，返回全量笔记和收藏数，不启动生成 |
| `GET /api/explore/feeds/:key` | 读取固化摘要/整理进度 |
| `POST /api/explore/refresh` | 主动刷新指定区域与分类 |
| `GET /api/explore/notes/:id` | 获取笔记、来源和地点卡片 |
| `GET /api/explore/favorites` | 当前用户的收藏笔记及关联地点，按收藏时间倒序 |
| `PUT /api/explore/favorites/:id` | 收藏笔记，重复请求不会重复添加 |
| `DELETE /api/explore/favorites/:id` | 取消当前用户收藏，重复请求保持未收藏 |
| `POST /api/trips/:id/conversation` | 创建或复用行程所属AI对话，可传已加入行程的 `placeId` |

分类参数为 `scenery`、`food`、`stay`、`fun`。固定范围请求额外传 `lng`、`lat`、`radius=10000`，服务端重新计算边界并执行圆形范围过滤；为兼容旧客户端仍接受5000米或仅边界查询，新界面固定使用10公里。所有行程与对话写入仍执行当前账号的归属检查；AI规划沿用登录要求。新加地点通过已有行程保存逻辑进入 `requirements.requiredPlaceIds`，AI调整会将其作为需要保留的地点，暂定时间不会锁定为固定预约。

方舟工具参数参考[Responses API](https://docs.volcengine.com/docs/ark/create-model-responses-api?lang=zh)，高德分类和周边查询参考[搜索POI文档](https://lbs.amap.com/api/webservice/guide/api-advanced/search)。是否能召回特定平台帖子取决于搜索工具可访问和收录的公开网页。
